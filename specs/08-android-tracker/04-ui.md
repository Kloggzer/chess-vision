# Phase 04 — UI, accessibility, settings, integration

## Why

Phases 01–03 delivered engine, geometry, and camera as disconnected modules.
This phase wires them into a running app and builds the product surface: a
clean Material 3 UI, first-class accessibility, and a settings screen holding
every feature toggle (look-forward, resolution, dynamic camera, experimental
board detection, tuning sliders).

## Design (decided — do not redesign)

Package `com.chesslab.tracker.ui` + `com.chesslab.tracker.service`. Single-activity
Compose app, `NavHost` with routes: `tracking` (home), `calibration`, `settings`,
`history`.

### Integration (`service/TrackerService.kt`)

Foreground service (camera type) owning: `TrackerCamera` → `BoardWarper` →
`TrackerEngine` loop on a dedicated dispatcher; `DynamicResolutionController`
wired to `BoardWarper.forResolution` on `activeResolution` changes;
`CornerDriftMonitor` polled every 5 s **only when** experimental detection is
enabled. Exposes `StateFlow<UiState>`. Extension points for later phases (define
now, leave null): `var safeguard: OccupancySafeguard?` (05), `var stateSink: GameStateSink?`
(06), `var recorder: SessionRecorder?` (07) — phases 05–07 plug in WITHOUT
editing UI files.

### Screens

- **Tracking (home):** digital board (Compose Canvas, rendered from FEN — no
  webview/SVG), SAN move list, status chip (state: Tracking / Hand over board /
  Stuck / Verifying), Undo + Reset buttons. Optional expandable **debug card**
  (off by default, toggle in settings) mirroring the Python one
  (`move_tracker/static/index.html:341-379`): fps, motion vs threshold, changed
  squares, z-values, best/second/margin, decider of last move.
- **Calibration:** live camera preview; tap 4 corners in enforced order
  **a8 → h8 → h1 → a1** with magnifier loupe on touch; "Suggest corners"
  button (experimental toggle on) runs `BoardDetector.detect`, then user
  confirms orientation by tapping which corner is a8. Wrong-orientation is the
  repo's classic silent-transpose pitfall — the confirm step is mandatory.
- **History:** move list with per-move decision provenance (decider, margin,
  vetoed squares) in a detail sheet; export entry point (phase 07 fills it).
- **Settings** (DataStore-backed, `SettingsRepository`):
  - *Game:* Look-forward (pair look-ahead) on/off; ambiguity margin (slider 0.5–5.0, default 2.0); move prior on/off.
  - *Camera:* Resolution (720p/1080p/4K); Dynamic resolution on/off.
  - *Detection (advanced, collapsed):* the Python live-tunables (`app.py:24-47`) —
    motion threshold, z threshold, census threshold, occlusion threshold, motion
    margin, overhang, motion hold, CLAHE clip (0–8). Each slider shows the
    default and a reset affordance.
  - *Experimental:* Automatic board detection (assist + drift monitor) — labeled "Experimental".
  - *Debug:* debug card on/off; overlay view picker (Board/Diff/Shadow/Occlusion/Motion —
    port of `/api/view` modes, colors changed=magenta, shadow=cyan, occlusion=orange per `tracker.py:2379`).
  - Later phases append sections: CNN (05), Spectator server (06), Recording (07).

Settings changes map to `TrackerConfig` copies; the service restarts the engine
with the new config only for non-live params, live-tunables update in place
(mirror the Python live/constructor split, `app.py:50`).

### Accessibility (binding, not best-effort)

- Every interactive element ≥ 48 dp, `contentDescription` on all icons.
- Move commits announced via `LiveRegion`/accessibility announcement: "White plays knight f3".
- Board Canvas exposes a semantics tree: each square focusable with piece description.
- WCAG AA contrast in both themes; test with Compose semantics assertions where feasible.
- All text in `strings.xml` (English), dynamic type respected (sp everywhere).

## Tests (write, run once, targeted)

- `./gradlew :app:assembleDebug` once at the end (allowed in this phase).

## Acceptance criteria

- [ ] App builds; tracking a synthetic feed via a fake `TrackerCamera` in a unit test produces UiState with moves.
- [ ] `grep -rn "contentDescription" android/app/src/main/kotlin/com/chesslab/tracker/ui` → hits on every icon-bearing screen.
- [ ] Calibration enforces a8→h8→h1→a1 order and has an orientation confirm for detected corners.
- [ ] All Python live-tunables from `app.py:24-47` exist as settings.
- [ ] Extension points (`safeguard`, `stateSink`, `recorder`) exist and are nullable no-ops.

## Do NOT

- No ONNX, no Ktor, no recording implementation — only their extension points.
- Do not hardcode strings in composables.
- Do not add a webview.
