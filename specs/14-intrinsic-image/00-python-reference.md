# Phase 00 — Python reference: intrinsic transform, entropy calibration, golden values

## Why

Python is the parity reference for the whole tracker. The transform, the calibration,
and the numeric contract (golden values) must exist here first so the Kotlin port
(phase 01) has something exact to match. Shadows currently reach the diff as gray
changes and are only suppressed after the fact by vetoes (HSV chroma, census-thr,
census-z, ZNCC — see `_apply_vetoes` path in `src/chesslab/move_tracker/tracker.py`
and Kotlin `Detector.applyShadowVeto`); the invariant image removes them from the
input signal itself.

## Design (decided — do not redesign)

New module `src/chesslab/move_tracker/intrinsic.py`:

```python
from dataclasses import dataclass
import numpy as np

@dataclass(frozen=True)
class IntrinsicCalibration:
    angle_deg: float   # theta*, 0..179
    lo: float          # P1 of I_theta* on the calibration frame
    hi: float          # P99; hi > lo guaranteed by calibrate()

def log_chroma(bgr: np.ndarray) -> np.ndarray:
    """HxWx3 u8 BGR -> HxWx2 float32 geometric-mean log-chromaticity (chi).
    Channels clamped to >=1 before log. Basis u1=(1/sqrt2,-1/sqrt2,0),
    u2=(1/sqrt6,1/sqrt6,-2/sqrt6) applied to (ln R~, ln G~, ln B~), R~=R/p,
    p=(R*G*B)**(1/3). NOTE: OpenCV is BGR — reorder to RGB before the basis."""

def invariant_gray(bgr: np.ndarray, calib: IntrinsicCalibration) -> np.ndarray:
    """HxWx3 u8 BGR -> HxW u8 invariant image:
    I = chi1*cos(theta) + chi2*sin(theta); u8 = clip((I-lo)/(hi-lo),0,1)*255."""

def calibrate(bgr: np.ndarray) -> IntrinsicCalibration:
    """Entropy minimization over theta in range(180) (1-degree steps):
    per theta take I values between P1..P99, bin width 3.5*std*N**(-1/3)
    (Scott), Shannon entropy of the normalized histogram; argmin wins.
    lo/hi = P1/P99 of the winning projection. Deterministic, no RNG."""

def entropy(values: np.ndarray) -> float:
    """Shannon entropy helper (exposed for tests)."""
```

Integration seam — `MoveTracker._gray` (tracker.py:933-944). The method currently
receives the warped BGR and does `cvtColor → CLAHE → blur`. New behavior:

```python
def _gray(self, warped):
    if self.intrinsic_calib is not None:           # intrinsic channel active
        g = intrinsic.invariant_gray(warped, self.intrinsic_calib)
        return cv2.GaussianBlur(g, (5, 5), 0)      # blur stays, CLAHE skipped
    ...existing path unchanged...
```

Config/wiring:
- `config.TRACK_DEFAULTS["intrinsic_gray"] = False` (comment: experimental,
  Finlayson intrinsic image; needs per-camera calibration).
- `MoveTracker.__init__` param `intrinsic_gray: bool = False`. When True, resolve
  the calibration from the profile (below); if the profile has none, log a clear
  warning once and fall back to the normal gray path (`self.intrinsic_calib = None`).
- Profile storage: add optional fields to the calibration profile dataclass in
  `src/chesslab/calibration.py` (find via `grep -n "class CalibrationProfile" src/chesslab/calibration.py`):
  `intrinsic_angle_deg: float | None = None`, `intrinsic_lo: float | None = None`,
  `intrinsic_hi: float | None = None`. YAML round-trip must tolerate old profiles
  (missing keys → None) — mirror how existing optional fields decode.
- CLI: new subcommand in `src/chesslab/cli.py`:
  `chesslab intrinsic-calibrate --profile <name> --source <src>` — grabs one frame,
  warps it with the profile (reuse the same warp helpers `MoveTracker` uses, find via
  `grep -n "warp_from_corners" src/chesslab/`), runs `calibrate()`, writes the three
  fields into the profile YAML, prints θ*/lo/hi and the entropy curve minimum.
- Live tuning: NOT live-tunable (needs calibration); do not add to
  `_live_tuning_kwargs` (move_tracker/app.py:24).

Golden values for phase 01: a deterministic 16×16 synthetic BGR array (seeded by
formula, not RNG — e.g. `bgr[y,x] = ((x*37+y*11)%251, (x*17+y*29)%251, (x*23+y*7)%251)`)
plus a fixed `IntrinsicCalibration(angle_deg=57.0, lo=-0.35, hi=0.42)`; write
`tests/data/intrinsic_golden.json` containing the input formula parameters, the
calibration, and the full 16×16 expected u8 output of `invariant_gray` as nested
lists. Generated by the test itself on first write? NO — commit the JSON, and the
test asserts against it (regeneration = deliberate, reviewed change).

## Tests (write, run once, targeted)

`tests/test_intrinsic.py`, run ONCE via `uv run pytest tests/test_intrinsic.py -q`:

1. `test_shadow_invariance` — synthetic textured BGR patch; multiply a region by
   0.5 (approx. Planckian shadow = scale on all channels); assert the invariant
   image changes by < 3 u8 levels mean-abs in that region while a *hue-swapped*
   patch (material change) moves > 25 levels.
2. `test_calibrate_recovers_angle` — build data along a known lighting direction
   in chi space (synthesize chi directly, back-project to BGR); assert
   `calibrate()` finds θ within ±3°.
3. `test_fixed_scale_temporal_stability` — same frame twice → identical u8 output;
   frame ×0.7 → mean-abs delta < 3 levels.
4. `test_golden_values` — formula-generated 16×16 input + committed calibration →
   exact match against `tests/data/intrinsic_golden.json` (tolerance ±1 u8).
5. `test_profile_roundtrip_optional_fields` — profile YAML without the new keys
   loads (None), with keys round-trips.
6. Targeted clip sanity (ONE clip, not the suite): replay
   `tests/data/testclips/blender-shadowsweep.mp4` with `intrinsic_gray=True` using
   a `calibrate()` result from the clip's first frame — assert the expected
   move count still commits (reuse the replay helper the clip tests use, find via
   `grep -rn "shadowsweep" tests/`). Mark this test `@pytest.mark.clips`.
