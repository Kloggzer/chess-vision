# `parity/` — golden fixtures generated from the Python move tracker

Generated by **`scripts/emit_parity_fixtures.py`** (phase 00b of `specs/17-android-rewrite`).
It drives the *real* `chesslab.move_tracker.tracker.MoveTracker` synchronously over the
committed Blender test clips (`tests/data/testclips/`) and dumps what Python computed.
**Never hand-edit anything in this directory.**

## Regenerate

```powershell
uv run python scripts/emit_parity_fixtures.py --all --out android/core-engine/src/test/resources/parity
```

The output is byte-stable: a re-run over an unchanged repo leaves
`git status --porcelain android/core-engine/src/test/resources/parity` empty. That is
guaranteed by a virtual clock, `sort_keys=True`, floats rounded to 6 decimals, sets emitted
as sorted lists, and `gzip(..., mtime=0)`. The script prints
`total: <bytes> (<MB>) over <n> clips` and exits non-zero above the **40 MiB** budget.

Use `ParityFixtures.kt` (same phase) to read all of it; it never touches the file system.

### Plane encoding — `"planeEncoding": "delta-u8"`

A plane file holds the **byte-wise difference to the previous emitted frame's plane of the
same kind**, gzipped (level 6, `mtime=0`), no header. Decoding is
`cur[i] = (prev[i] + delta[i]) & 0xFF`, starting from an all-zero buffer for the first frame
in `meta.frames` / `meta.framesWithBgr`. On these near-static board renders this costs a
factor of ~4 in size and is what makes 18 clips fit in the budget. `ParityClip.gray()` /
`ParityClip.bgr()` do the walk for you (cached — iterate frames in ascending order).

### Sampling — the fixture *is* the input stream

The tracker is fed **exactly the frames listed in `meta.frames`** — subsampling happens at
decode time, not at emit time. So the fixture is a complete, self-consistent replay: a
Kotlin engine fed the same planes in the same order must produce the same decisions, with
no hidden inputs. `meta.sampling` records the rule (warm-up run, a dense window around each
commit, every Nth frame elsewhere); `meta.replayedSans` is what this frame stream actually
produced and `meta.sanMatchesManifest` says whether that equals the manifest's
`erwartete_zugliste`.

| `whitePov`, `overhang`, `censusZWeight` | geometry + evidence knobs in force |

| `cropBorderPx`, `cropPadUp`, `cropPadSide` | crop-warp geometry (`calibration.py`) |

| `replayedSans`, `replayedFen`, `sanMatchesManifest` | what this replay produced |

### `meta.json -> effectiveConfig` — BUILD YOUR `TrackerConfig` FROM THIS

**Kotlin parity tests MUST construct `TrackerConfig` from `effectiveConfig`, never from
Kotlin defaults.** Use `ParityEffectiveConfig.toTrackerConfig()` in `ParityFixtures.kt`.

It holds *every* field of `TrackerConfig` (43 settable + the 4 derived members
`settleFrames` / `avgFrames` / `confirmFrames` / `detSize`), keyed by the Kotlin property
names and read off the **live** `MoveTracker` instance after construction. The generator
aborts if a single field is missing, so a knob added to the seam cannot go unfixtured.

Why this matters: the fixtures come from `MoveTracker.__init__` defaults **plus** the clip
manifest overrides, while `TrackerConfig`'s own defaults follow `config.TRACK_DEFAULTS`.
Those two disagree — `occlusionColorThr` is **1.5** here and **3.0** there. A test that
uses Kotlin defaults diverges on Tier B for a reason that looks exactly like a port bug.

Two traps:

- `settleFrames` / `avgFrames` / `confirmFrames` are **CNN-conditional functions** in
  `TrackerConfig` but plain constructor overrides in Python. `blender-castle` sets
  `confirm_frames: 3`, which the seam cannot express — read these three from
  `effectiveConfig`, not from `TrackerConfig`.
- `cnnOn` is **false** for every fixture (`cnn_run=None`), so the CNN-side knobs are the
  Python defaults and no verify/recovery path was exercised.

Rules:

- **`tierB` is on every emitted frame**; its fields are the tracker's live debug state, so
  they are *sticky* — `changed`/`bestLl` keep the last computed values while
  `detectionRan == false`. A Kotlin port carries the same state, so compare frame by frame.
- **`tierA` is non-null only where the tracker actually computed detection evidence**
  (`tierB.detectionRan == true`). Elsewhere it is `null`: there is no `cur`/`ref` pair to
  attach the primitives to. Every clip has at least six tier-A frames.
- `curFrames` lists the emitted frames averaged into `cur` (`_RunningMean.mean_uint8`, i.e.
  `(sum / n).astype(uint8)` — truncation, not rounding). `refFrames` is the same for the
  reference, or `null` after `_maybe_patch_anomaly` mutated `ref_gray` in place.
  Both let a consumer reconstruct the exact input pair from the planes.
- `gamut` is emitted only on the frame where `board_color_gamut` was rebuilt (invariant 6:
  only a quiet re-anchor rebuilds it, never `_set_ref(from_commit=True)`);
  `activeGamutFrames` on every tier-A frame says which emitted frames the *currently
  active* gamut was built from.
- `squareRegion` / `squareToCropBox` are emitted once, on the first tier-A frame, for all
  64 squares; `null` afterwards. The full parameter cross-product lives in `_geometry/`.
- `censusCodeCrop` is `census_transform` over one fixed 16x16 crop (top-left =
  `square_region("e2", detSize, whitePov)[0:2]`), enough to pin bit order, replicate
  padding and `eps == 0`.
- `loglikScores` / `loglikPairScores` are the **top 12**, in Python's order (ties keep it).
- The census channel is emitted **raw and normalized** (invariant 8: `censusThr` compares
  against the RAW channel; `censusNormalized` feeds scoring and noise).
- `noiseZ` is `noise.z(normalizedDiffs)` **before** that frame's update; `noiseMean` /
  `noiseStd` are the model **after** it. A port that mis-orders learning vs. scoring
  diverges on the very next frame.
- `commit` is `null` on frames that commit nothing; a multi-move commit uses
  `{"ucis": [...], "sans": [...], "fenAfter": ..., "decider": ...}`.

## `_cnn/` — synthetic, model-free

Built from **hand-constructed probability arrays over real FENs**, not from a trained run:
`observation_from_probs`, `score_moves`, `verify_move`, `board_matches_identity`,
`derive_moves_identity/deep`, `resync_check`, `has_occupancy_conflict` and
`guess_illegal_move` are all pure given probabilities and a board. Deterministic, tiny, and
it tests the logic instead of the weights.

Each row carries `{name, fen, classes, confThr, probs: {sq: [n floats]}, …expected}`.
`probs` puts the target confidence on the intended class and spreads `1 - conf` over the
rest with weights from `random.Random("<seed>:<square>")`, seed **20260724**
(`_cnn/meta.json -> seed`). Covered: confident/unconfident squares, an occluded hand, the
`pOccluded >= 1 - thr` gate boundary, a 13-class run (no `occluded`), a mislabelled knight,
promotion variants (0-square margin), local verify with a far misread, castling with `f1`
occluded, 31-vs-32 label-confident boards, single/blitz-pair/deep 4-ply derivation, two
transposition orders, a nonsense observation, and the resync/guess conflict patterns.

## `_geometry/resolve_corners.jsonl`

`resolve_board_corners` from synthetic marker point sets — 4 markers (square, perspective,
rotated, scaled), 3 (affine parallelogram), 2 (similarity, adjacent/diagonal/rotated), a
degenerate 2-point case, 1 and 0 markers (both `null`), across `boardSize` 320/640/800/1600.
Rows are `{name, pointsById, boardSize, corners|null, nUsed|null}`.

## `_geometry/grid_coverage.jsonl`

`_grid_line_coverage` on self-contained **raw**-gzipped gray planes under
`_geometry/planes/`: real warped clip frames (clear board, hand over the board) plus a clean
synthetic grid, the same grid with a blanked band, a flat image and an 8x8 size-guard image.
Rows are `{name, plane, width, height, coverage}`.

Tier A and Tier B are consumable from the committed planes alone — **no JavaCV, no OpenCV
in `:core-engine` tests**. Tier C lives in `<clip>/natives/` and its own `meta.json` carries
`"requiresNatives": true`; the clip-level `meta.json` says `"requiresNatives": false`
because A and B do not need them.

## Tolerance contract (binding)

Enforced by `ParityFixtures.kt`:

- **Floats:** `abs(e - a) <= 1e-4 * max(1.0, abs(e))` — relative, with a `1e-4` absolute
  floor (`assertClose`, `assertCloseMap`).
- **Everything else EXACT:** every set (`changed`, `shadowVeto`, `tainted`, occlusion sets),
  every decision string (state, UCI, SAN, FEN, stuck reason, decider), every count
  (`assertExact`, `assertExactList`).
- **Documented exception** (`01c-shadow-gamut.md`): a hand-rolled BGR->HSV/Lab conversion
  may differ from OpenCV by **<= 1 LSB per channel** (OpenCV uses integer LUTs). The
  *derived square sets* must still be exact.

A tolerance may never be loosened to make a test pass — a mismatch is a port bug or a
`STATUS.md` discrepancy.

## Known gaps

- `blender-italian` and `blender-opera` are **not emitted**: they do not fit the 40 MiB
  budget (see `index.json -> skipped`). All 13 clips the phase file requires are present.
- All 18 emitted clips reproduce their manifest move list
  (`index.json -> tierBDegraded` is empty). If a future regeneration degrades a clip, its
  `meta.tierBComplete` goes false and it must be excluded from the strict Tier-B gate —
  never silently accepted.
- `occlusion_color_thr` is **1.5** in these fixtures (the `MoveTracker` constructor
  default), not the `3.0` of `config.TRACK_DEFAULTS` that `TrackerConfig` uses. The clips
  do not override it and `replay_clip`/`tests/test_clips.py` do not either. Always read the
  threshold from `effectiveConfig.occlusionColorThr` / `tierA.occlusionColorThr` /
  `baselineOcclusion.colorThr`, never hard-code.
- No ArUco *detection* fixture exists (clips replay with `live_align=False`); the pure
  `resolve_board_corners` half is covered by `_geometry/resolve_corners.jsonl`.
